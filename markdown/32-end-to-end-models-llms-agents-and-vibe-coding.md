# 第32章 端到端模型、LLM、Agent与Vibe Coding

## 第1节 四类概念的边界

机器学习、端到端模型、大语言模型和 Agent 经常被混在一起，实际解决的问题并不相同。

- **传统机器学习：** 从人工构造的特征预测收益、风险、类别或排序；
- **端到端模型：** 尽量从较原始的数据直接学习信号、权重或决策；
- **LLM：** 处理文本、代码、知识和自然语言交互；
- **Agent：** 让模型围绕目标规划步骤、调用工具、读取状态并交付结果；
- **Vibe Coding：** 通过自然语言描述目标，由编码智能体快速实现和迭代软件。

在量化投资中，它们可以组成同一条研究链路，但不能互相替代。LLM 可以从公告中提取事件，机器学习模型可以把事件特征映射为收益预测，组合模型负责仓位，Agent 则协调数据、代码、回测和报告。

## 第2节 端到端量化模型

端到端模型减少人工定义的中间步骤，常见映射包括：

```text
价格序列 → 收益预测
订单簿 → 短期价格或成交概率
多资产特征 → 横截面排序
原始信号 → 组合权重
市场状态 → 交易动作
```

端到端不等于把所有工作交给一个黑箱。训练目标中仍应加入换手率、交易成本、风险暴露、杠杆、流动性和仓位约束。否则模型可能在预测指标上表现良好，却无法形成可交易组合。

### 监督学习

以未来收益、方向、排名或风险为标签。主要问题是标签重叠、非平稳、噪声大和样本外衰减。

### 自监督学习

通过掩码重建、对比学习或序列预测学习市场表示，再用于下游任务。它可以利用大量无标签数据，但表示质量仍需通过真实投资任务验证。

### 强化学习

将仓位或订单视为动作，将收益、风险和成本纳入奖励。环境模拟误差、策略不稳定和样本效率是主要挑战。

### 可微分组合与执行

将排序、权重、风险约束或执行损失嵌入训练过程，使模型直接优化更接近投资目标的指标。实现时必须防止通过未来数据、不可执行价格或不现实撮合获得虚假优势。

## 第3节 LLM在量化投资中的应用

LLM 的优势主要位于非结构化信息和研究交互层。

### 文档理解

- 从年报、公告和政策文件中抽取结构化字段；
- 识别业绩预告、回购、并购、分红、强赎等事件；
- 比较同一公司不同时期的措辞和风险披露；
- 从会议纪要中提取观点、证据和待办事项。

### 研究辅助

- 生成检索式和研究问题；
- 解释模型、代码和异常结果；
- 将研究假设转化为可测试步骤；
- 生成数据字典、实验记录和研究报告初稿；
- 对策略逻辑、数据泄漏和回测假设进行审查。

### 文本因子

LLM 可以参与分类、实体识别、关系抽取、情绪分析和事件编码。所有输出都应保存原始文本、提示词、模型版本、时间戳和引用片段，以便复现与审计。

LLM 不应直接被当作可靠的未来价格预言器。自然语言回答流畅，不代表信号稳定；模型知识也不等于当时可获得的信息。

## 第4节 Agent的组成

一个可用的 Agent 通常包含：

1. **目标与约束：** 明确任务、权限、预算和停止条件；
2. **模型：** 负责理解、规划和生成；
3. **工具：** 搜索、数据库、代码执行、文件、浏览器和业务API；
4. **状态：** 保存任务进度、中间结果和外部环境；
5. **知识：** 通过文件、数据库或RAG获得可追溯信息；
6. **验证器：** 检查结构、数值、代码、引用和风险；
7. **审批点：** 在交易、写库、发布或删除前交由人工确认；
8. **追踪与评估：** 记录工具调用、失败、成本和结果质量。

Agent 的价值不在于“像人一样聊天”，而在于能够围绕目标执行可观察、可暂停和可审计的工作流。

## 第5节 常见编码与办公Agent

以下产品定位和能力会持续变化，使用前应查看官方文档、账户权限和数据政策。本节只介绍基本定位，不进行性能排名。

### Claude与Claude Code

Claude 是 Anthropic 的通用模型与助手产品；Claude Code 更侧重智能体式软件开发，可以理解代码仓库、编辑文件、运行命令，并通过项目说明文件和 MCP 等机制连接外部工具。它适合代码解释、重构、测试、调试和多步骤工程任务。

在量化研究中，可用它检查数据处理代码、实现回测原型、补充测试或解释模型。涉及数据库写入、交易接口和密钥时，应使用最小权限并保留人工审批。

官方入口：[Claude Code Documentation](https://docs.anthropic.com/en/docs/claude-code/overview)

### Codex

Codex 是 OpenAI 的编码智能体，用于编写、审查和调试代码，并可通过 IDE、CLI、网页、移动端或 SDK 等方式进入软件开发流程。它适合直接在项目中读取上下文、修改文件、运行测试和完成有验收条件的工程任务。

在量化项目中，Codex 可以用于数据库迁移、因子实现、回测修复、测试生成、研究文档和工程维护。高质量任务应给出数据边界、验收测试、性能要求以及禁止触碰的生产资源。

官方入口：[OpenAI Codex Documentation](https://developers.openai.com/learn/codex)

### WorkBuddy

WorkBuddy 是腾讯推出的办公智能体工作台，面向文件处理、文档、表格、PPT、数据分析、调研和多智能体协作等场景。其特点是围绕办公交付物组织任务，并在授权范围内访问本地文件或企业工具。

在量化团队中，它更适合整理研究材料、批量处理文档、形成汇报、汇总数据和编排非交易型办公流程。是否允许接触原始数据、内部研报或客户信息，应由企业权限和合规制度决定。

官方入口：[WorkBuddy产品介绍](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Product-Guide)

### 千问办公

千问办公面向文档处理、内容生成、数据分析、会议纪要和企业办公流程，并可与钉钉等办公生态结合。它强调从自然语言目标到文档、表格、PPT或分析报告等可继续使用的产物。

对量化研究而言，可用于年报阅读、行业资料整理、会议纪要、可比公司信息和研究汇报，但关键数字仍应回到原始数据和正式数据库校验。

官方入口：[千问办公](https://qwenwork.cn/)

### 豆包工作

豆包工作面向写作、研究、文档理解、内容生成和任务执行等生产力场景。它适合作为通用办公助手处理资料、形成初稿和组织多模态内容。

在量化场景中，可以用于资料摘要、研究问题拆解、图表说明和报告草拟。涉及投资结论时，应明确区分资料整理、模型输出和最终决策，避免把自然语言生成结果直接当作交易信号。

官方入口：[豆包](https://www.doubao.com/)

### 如何选择

| 类型 | 主要工作对象 | 更适合的任务 | 关键风险 |
|---|---|---|---|
| Claude Code、Codex | 代码库、终端、测试和开发工具 | 因子代码、回测、数据库、测试、应用开发 | 越权修改、错误代码、密钥和生产环境风险 |
| WorkBuddy | 本地文件与办公交付物 | 批处理、文档、表格、PPT、调研 | 文件权限、敏感数据外泄 |
| 千问办公 | 办公文档与组织协作 | 纪要、报告、数据分析、钉钉流程 | 企业权限、数字与来源校验 |
| 豆包工作 | 通用内容与任务 | 摘要、写作、研究初稿、多模态内容 | 幻觉、引用和结论可靠性 |

选择产品时应先看任务和权限，再看模型能力。编码智能体与办公智能体可以互补：前者负责可测试的软件和数据流程，后者负责文档、协作和交付物。

## 第6节 量化研究Agent体系

量化平台可以按职责拆分 Agent：

- **数据Agent：** 拉取、校验、去重和登记数据版本；
- **文档Agent：** 解析公告、财报、研报和政策文件；
- **研究Agent：** 形成假设、生成特征并提出实验方案；
- **编码Agent：** 实现代码、测试和数据库变更；
- **回测Agent：** 运行实验并检查泄漏、成本和稳健性；
- **风险Agent：** 检查暴露、容量、极端情景和约束；
- **报告Agent：** 汇总证据、结果和限制；
- **监督Agent：** 检查任务是否完成、证据是否充分。

多 Agent 不一定优于单 Agent。职责拆分应服务权限隔离、上下文管理和独立验证，而不是为了增加角色数量。

## 第7节 Vibe Coding在量化研究中的使用

Vibe Coding 的典型流程是：用自然语言描述目标，让编码智能体生成实现，通过运行结果继续反馈和迭代。它适合快速制作数据工具、研究页面、可视化、因子原型和一次性自动化任务。

量化代码具有更高的验证要求。推荐工作流是：

1. 先写研究假设、数据口径和验收标准；
2. 要求智能体先读取现有项目和数据字典；
3. 从最小可运行实现开始；
4. 为复权、交易日、缺失值和时间边界编写测试；
5. 与简单基准模型对照；
6. 检查未来函数、幸存者偏差和不可交易价格；
7. 在样本外和不同市场阶段验证；
8. 由人审查后再合并或部署。

Vibe Coding 可以降低表达想法与实现代码之间的摩擦，但不能省略测试、评审和研究记录。

## 第8节 评估与治理

Agent 评估不应只看回答是否“像对的”。至少应衡量：

- 任务完成率和人工返工率；
- 事实、数字和引用准确率；
- 代码测试通过率和回归缺陷；
- 工具调用成功率和重试次数；
- 运行时间、模型成本和资源消耗；
- 数据泄漏、越权访问和提示注入事件；
- 不同模型版本下的稳定性；
- 人工审批前后的错误拦截率。

生产环境应实行最小权限、密钥隔离、网络边界、沙箱执行、操作审计和高风险动作审批。Agent 可以提出交易或数据库变更，但不应默认获得无限制执行权。

## 第9节 推荐落地顺序

1. 从只读的文档总结和代码解释开始；
2. 增加结构化抽取和引用校验；
3. 接入隔离的研究数据库和代码沙箱；
4. 允许生成代码，但必须运行测试；
5. 编排回测与报告流程；
6. 引入独立风险检查和人工审批；
7. 最后才考虑连接模拟交易或受限生产系统。

可靠的 AI 量化系统不是让 Agent 取代研究员，而是把人的判断、模型能力、工具执行和验证机制组合成更高质量的研究过程。
