# 第0章 前言

## 为什么写这本书

量化投资早已不再等同于“用程序选股票”。一个完整的现代量化体系，需要同时理解资产定价、市场机制、数据、统计、机器学习、组合管理、风险、执行和工程系统。研究对象也不应局限于股票：ETF、LOF、债券、可转债、商品、期货、期权、外汇和 REITs，都可以在统一的收益—风险框架下被研究和配置。

与此同时，量化研究的生产方式正在改变。过去，研究员主要通过手工查资料、编写代码、清洗数据和反复调试来完成策略研究；现在，大语言模型可以辅助阅读财报、公告、研报和政策文件，Agent 可以连接数据、代码、回测和知识库，Vibe Coding 则显著降低了从想法到原型的门槛。工具变得更强，但科学研究的基本要求没有改变：假设必须明确，数据必须可追溯，实验必须可复现，结果必须经过样本外验证，风险必须能够解释。

《量化投资精要》试图把这两个方向放在同一张地图中：一方面建立跨资产、跨策略的量化投资知识体系；另一方面解释 AI 原生工具如何进入真实的研究和投资工程流程。

## 本书的组织原则

全书不简单按照“股票策略”“期货策略”罗列技巧，而是区分四个层次：

1. **底层资产：** 股票、债券、商品、外汇、房地产和现金类资产；
2. **交易工具：** 个股、现券、期货、期权、ETF、LOF、可转债和 REITs；
3. **策略逻辑：** Beta、多因子、择时、趋势、Carry、套利、波动率、事件驱动和资产配置；
4. **研究流程：** 数据、建模、回测、组合、执行、风险、监控和迭代。

这种结构能够避免把资产、产品和策略混为一谈。例如，ETF 是交易载体，不是单一资产类别；它既可以承载股票，也可以承载债券、商品或跨境资产。动量也不是股票独有的策略，它可以用于行业、ETF、期货、外汇和多资产配置。

## 关于机器学习、端到端模型与人工智能

本书把传统多因子模型和机器学习模型分开讨论。传统多因子强调经济含义、线性暴露和可解释性；机器学习擅长处理非线性、交互效应和高维特征。两者不是替代关系，而是不同复杂度下的建模工具。

端到端模型进一步减少人工划分的中间步骤，尝试从原始数据直接学习信号、权重甚至订单。但端到端并不意味着不需要金融约束。交易成本、换手率、流动性、风险预算、仓位边界和可解释性仍应进入训练与评估过程。

LLM 更适合处理文本、知识和研究流程，而不是被简单当作价格预测器。它可以辅助完成信息抽取、事件识别、研究综述、因子假设生成、代码解释和报告撰写。Agent 则把模型与数据库、搜索、代码执行、回测、风控规则和审批流程连接起来，使研究过程可以被编排、记录和复核。

Vibe Coding 让研究员能够通过自然语言快速生成代码和应用原型，但“生成得快”不等于“结果可靠”。量化场景中的代码必须经过数据边界检查、单元测试、基准对照、回测审计和人工复核。AI 可以降低实现成本，却不能替代研究责任。

## 关于编程语言和数据库

本书只介绍 R 和 Python 的基本定位、安装方式、环境管理以及与量化研究直接相关的软件包，不试图替代通用编程教材。读者应把语言看作实现研究流程的工具，而不是学习目标本身。

随着数据规模增长，单纯依赖 CSV 和内存中的 DataFrame 很快会遇到性能、版本和协作问题。因此，本书增加数据库与数据架构内容：DuckDB 适合本地分析和直接查询 Parquet；MySQL 适合结构化业务数据、权限和事务管理；Redis 适合缓存、实时状态、消息流和低延迟读写；PostgreSQL、ClickHouse、SQLite、对象存储与列式文件则覆盖其他规模和场景。选择数据库的关键不是追求“最强”，而是让数据的访问方式、更新频率、并发要求和一致性需求相匹配。

## 如何阅读本书

初学者可以从基础理论和市场工具开始，再选择一种资产和一种策略完成完整研究。已有经验的读者可以按问题跳读，例如直接进入套利、组合优化、数据库或 LLM/Agent 章节。工程人员则可以重点关注数据治理、数据库、回测、执行和研究工作流。

无论采用哪条路径，都建议围绕同一个闭环学习：

> 提出假设 → 获取数据 → 构造信号 → 样本外验证 → 建立组合 → 计入成本 → 分析风险 → 模拟执行 → 持续监控

量化投资的价值不在于制造复杂，而在于用清晰、可检验和可复现的方法处理不确定性。本书希望提供的，正是这样一套可以持续扩展的研究框架。
